### Log-Sentinel AI分布式日志智能诊断中台
- **项目时间**：2025.11 ~ 2026.02
- **技术架构**：Spring Boot 3、LangChain4j、Kafka、Redis、Milvus、JavaParser、GitLab API、Gemini、Qwen
- **项目背景**：为解决微服务集群线上报错排查耗时长的痛点，主导设计开发了基于大模型与 RAG 架构的旁路日志辅助分析系统，设计目标为支撑公司多微服务集群的平滑接入。
- **核心职责与技术亮点**：
  - **日志防抖与限流**：Caffeine + Redis 两级缓存对报错堆栈做分布式去重，10 分钟窗口内同类异常只诊断一次，避免 Token 浪费；LLM 推理走独立线程池（CallerRunsPolicy 模式），配合 DLQ 死信队列防止消费者 Rebalance。
  - **AST 源码注入**：接入 GitLab API 按 serviceName 动态拉取源码，通过 JavaParser 解析 AST 精准提取报错行所属的完整方法块并标注 `[ERROR LINE]` 作为核心 Context 喂给 Agent，从根源上降低了大模型在排障场景下的“幻觉”率。
  - **RAG 知识闭环与重排优化**：将高价值人工诊断经验经 Embedding 向量化沉淀至 Milvus 数据库。在报错诊断前进行历史方案的 Top-K 召回与重排（Rerank）增强 Prompt；构建企微告警卡片的“点赞/踩”反馈按钮，实现失效诊断知识的自动衰减与淘汰闭环。
  - **垂类模型私有化微调**：针对长文本输入导致输出格式不稳定的问题，基于脱敏排障记录构建 Alpaca 数据集，用 LLaMA-Factory 对 Qwen 做 LoRA 微调（rank=8, epoch=3），微调后输出稳定对齐内部 SOP 格式，精简了约束性 System Prompt，降低了推理 Token 开销。

- **项目时间**：2023.02 ~ 2024.03
- **技术架构**：SpringBoot、SpringCloud Alibaba、MySQL、TDengine、Mybatis Plus、Redis、Kafka、EMQX、Netty、ELK
- **项目背景**：面向运营商的终端业务管理系统，支撑平台超 200万 设备的日常运营、指令下发与状态监控。
- **核心职责与技术亮点**：
  - **百万级并发网关改造**：主导设备通信协议迁移至 MQTT，依托 Nginx SSL 反向代理接入 EMQX，稳定支撑 150 万日活高并发在线；针对不支持 MQTT 的老旧设备，基于 Netty 实现了自定义 TCP 协议网关并攻克字节粘包问题，实现全系统设备统一纳管。
  - **高吞吐消息链路重构**：引入 Kafka 承接峰值 3000 QPS 入/1000 QPS 出的消息洪峰。自研基于 Key Hash 的顺序消费线程池保障单设备消息时序；依托策略模式重构消息分发中心，严格遵循开闭原则。
