# 爱商在线 - 面试复盘 (0706 下午 1:30)

## 📊 面试基本情况
* **面试岗位**：AI 中台 / AI Agent 架构研发及项目负责人（偏重实战与项目管理）
* **期望薪资**：20k - 25k
* **团队现状**：公司目前有人在做 AI，但非 100% 投入，急需一个能 100% 投入并能承担项目负责人的角色。

---

## 🌟 核心亮点与优势
1. **实战经验稀缺**：在过去两年内成功落地了企业内部的 AI Agent 项目（日志诊断系统、代码审查系统）。
2. **微调实操经验**：了解云端与本地小模型的痛点，熟练使用 LLaMA Factory 对模型进行指令微调，解决大模型 JSON 输出不规范的问题。
3. **架构选型思考**：能根据项目生态（Spring 生态选 Spring AI，灵活度要求高选 LangChain4j）给出合理的选型建议。
4. **工作流设计能力**：在代码审查项目中设计了 Git Webhook -> Git diff -> LangGraph 多 Agent 分发 -> Human in the loop 的完整协同链路。

## ⚠️ 待改进与反思（避坑指南）

### 1. 项目动机表达过于“被动”，缺乏“负责人”气场
* **场景重现**：“响应公司号召嘛，老板就说我们公司内部去使用这个AI工具去提效嘛。然后让我们去看能不能在我们系统里面使用到这个AI嘛。”
* **问题反思**：连续使用“响应号召”、“老板让做”等词汇，使自己显得像个被动的执行者。高级岗位更看重自驱力和技术视野。
* **高分话术**：“当时我敏锐地观察到团队在日常排障和代码审查上耗费了大量人力。结合当下大模型的发展，**我主动向主管提议并立项了**这个 AI 诊断系统，致力于用技术手段为研发团队降本增效。”

### 2. 硬件资源描述过于随意、口语化
* **场景重现**：“我们的配置其实配置很拉垮，2080ti好像是8G显存的，其实就是我们之前的服务器拼凑出来的。”
* **问题反思**：“拉垮”、“拼凑”等词汇不够专业，容易削弱项目的技术含量。
* **高分话术**：“当时我们处于**算力资源受限（Resource-constrained）**的环境。为了在有限的硬件下跑通模型，我专门做了调研，采用了 9B 的小模型并结合指令微调策略，成功在轻量级算力下实现了业务闭环。这也是我们在大模型低成本私有化部署上的一次成功探索。”

### 3. JVM 底层知识暴露致命短板
* **场景重现**：面试官问“给你个内存快照你会分析吗？”，回答“我记得内存快照可以看出每个调用的方法的堆栈使用情况……是的，我还是使用 arthas 比较多一点”。
* **问题反思**：概念张冠李戴。将“内存快照(Heap Dump，看对象和引用链)”和“线程快照(Thread Dump，看堆栈)”搞混。
* **改进动作**：重点复习 `prep/jvm-troubleshooting.md` 中的 MAT 离线分析标准流程（Histogram、Dominator Tree、GC Roots）。

### 4. 求职意愿与承压能力略显“畏难”
* **场景重现**：面试官强调“招进来需要当项目负责人，压力比较大”时，回答“做纯开发的去接入这个压力会比较大”。
* **问题反思**：面试官是在做压力测试。表现出顾虑会让对方认为你无法承担项目推进的重任。
* **高分话术**：“我非常认同，AI 中台需要极其扎实的底层基础和项目落地能力。我也非常渴望能在一个真正把 AI 作为核心基座的团队里，承担起技术攻坚和项目推进的责任，我不怕压力，反而觉得这非常有挑战性。”

### 5. 团队规模与协作模式描述易暴露短板
* **场景重现**：当被问到团队规模时，回答“我们最近一年团队人员比较少……去年五六个后端，今年裁掉了安卓，目前只有两个后端一个前端。”
* **问题反思**：过于诚实地交代“人员流失”，容易让人觉得团队在走下坡路或缺乏规范。对于想应聘“项目负责人”的候选人，应当将“人少活多”转化为展现全栈能力和高效协作模式的优势。
* **高分话术**：“目前我们这个业务线采用的是**敏捷开发（Scrum）模式**，是一个非常精简但高效的闭环小队（2后端+1前端）。正因为团队规模精简，我不仅负责核心代码编写，还承担了技术选型以及部署落地。为了在人力有限的情况下保证代码质量，**我还主导引入了基于大模型的 Code Review Agent 机制**，把原来需要人工互审的环节自动化了，这也是我们在小团队下保持高效交付的技术沉淀。”
